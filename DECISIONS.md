# Decisions

One line per real choice, and the reason. This is the answer key for "walk me through your
architecture" — and the fastest way to reconstruct why a file looks the way it does after the code has
moved on. Ordered by layer, not by date: the interesting ones are the trade-offs, so each entry names
what was given up.

## Orchestration

| Decision | Why | What it cost |
|---|---|---|
| LangGraph `StateGraph` over four chained function calls | The critic→synthesis edge is a **cycle**; a chain needs recursion plus a hand-rolled counter, and `stream_mode="updates"` gives per-node progress for free | A dependency, and a state schema to maintain |
| Revision ceiling `MAX_REVISIONS = 2`, enforced in `should_revise` | The first rewrite fixes a real defect, a second is usually the critic and the model talking past each other, and a third spends Groq quota without changing the answer | A genuinely hard-but-wrong answer still ships after two passes |
| Put the loop bound in the routing function, not the critic | One place owns the ceiling, so editing the graph cannot silently remove it | A second file to read when tracing the loop |
| Typed `AgentState` (`TypedDict, total=False`) | Nodes update a subset of keys; `total=False` says so, and a typo becomes an error at the node that introduced it instead of a missing value at the far end | Slightly awkward `state.get(...)` everywhere |
| `trace` is `Annotated[list, operator.add]` | LangGraph's default channel overwrites, so every node would erase the history and the UI would show only "finalise" | One non-obvious annotation to explain |
| Chunks travel through state as plain dicts, not pydantic models | LangGraph merges state by key; swapping a model instance for a dict mid-chain is a subtle bug class, so the conversion happens once at the prompt boundary | Two representations of the same thing, deliberately |
| Compiled graph cached with `lru_cache(maxsize=1)` | A per-request compile rebuilds the node registry for no benefit, and the free tier's 0.1 CPU makes that measurable | No per-request graph variation (not needed) |
| The router prompt carries the scoped filenames, not just the question | "what is this document?" against one selected file is an unambiguous summary request, and a classifier that cannot see the referent reads a demonstrative as vagueness and refuses to answer. Real users hit this in the first minute | One small Mongo read per turn (`filenames_for` on ids already resolved by `POST /api/chat`), and a router that must be told rather than inferred |
| `parse_route` reads the `LABEL:` line and matches whole words, earliest first | Scanning the whole reply let a reason overwrite its own label — "LABEL: CLARIFY / REASON: user wants to search" routed as a search — and iterating a `set` of the four words made the winner depend on hash order, so one reply could route two ways in two processes | A format assumption (`LABEL:`/`Route:`) that a model could ignore; the whole-reply scan stays as the fallback |

## Retrieval and grounding

| Decision | Why | What it cost |
|---|---|---|
| Filter `owner_id` inside the Pinecone query, not after | Cross-user leakage is a correctness bug, not only a privacy one; a caller cannot forget a filter that is built into the service | One less flexible ad-hoc query path |
| Pass the scope as `filter=`, singular, and say so in a comment | `pinecone.Index.query` ends in `**kwargs`, so the earlier `filters=` was valid Python that the client simply dropped — the query ran unscoped and owner isolation disappeared without an error, a log line, or a failing test | A keyword pinned to one SDK's spelling, with a test that reads the installed signature |
| Cosine score floor 0.18 instead of always returning `top_k` | Six chunks where three score well is three pieces of evidence plus three distractions the model will happily cite | Recall drops on genuinely thin corpora |
| One unfiltered re-rank when the floor returns nothing **and** ≤ 3 documents are in scope | "What is this document?" is about a file as a whole, so it shares no vocabulary with any passage inside it — measured against the document it names, cosine is 0.08 and the floor calls the right file noise. With a handful of files open the referent is settled, so the ranking is worth a second query | One extra Pinecone round trip on the zero-hit path, and the exception has to be re-fenced against a wide scope or it defeats the floor entirely |
| Collapse exact duplicate chunks after search | Overlap seeding puts a boundary sentence in two consecutive chunks; retrieving both wastes a slot the user paid for | A cheap O(n) pass, and no fuzzy dedupe |
| Numbered `[1] [2]` passages in the prompt, citations generated from the same list in the same module | The model needs something to point at, and a citation off by one is worse than none — it points at a passage that does not support the claim | Prompt looks annotated, and the model must be told to use the markers |
| Zero hits short-circuit to `finalise` | Asking a model to answer with no evidence buys a fluent, unsourced guess — and two Groq calls to produce it | "Not found" is a distinct code path, not a model output |
| Chunk ~1000 chars with 150 overlap | An answer sitting on a boundary would otherwise be split into two unusable halves | Duplicate text, which retrieval must collapse |
| Local `all-MiniLM-L6-v2` embeddings | $0 per chunk and no rate limit on the step that runs once per chunk, while Groq throttles everything else | Weaker than a hosted 1536-dim model; stated in Known limitations |
| Documents and queries embed through one module | Vectors from different models live in unrelated spaces and the cosine between them means nothing | A startup check that raises if dims disagree with config |
| Chunk text stored in Pinecone metadata, not Mongo | Atlas M0 is a hard 512 MB cap, and Pinecone needs the text attached anyway to build a citation without a second lookup | Two stores to keep in sync on delete |

## Agents and prompts

| Decision | Why | What it cost |
|---|---|---|
| `temperature=0.2` for synthesis, `0.0` for router and critic | The task is "say what the documents say and cite it"; creativity here is hallucination, and a hotter draft gets rejected — wasting the call that produced it | Stiff prose, deliberately |
| Unparseable critic output counts as **pass** | Failing on garbage would spin the revision loop into the same unreadable response and burn quota | A silent pass when the critic misbehaves |
| Router's tolerant `parse_route` (scan for a known word, default `search`) | Instruction-following models answer "LABEL: SEARCH", "search", and "Route: SEARCH - needs the contract" | A misrouted turn is possible; the search path handles it |
| Every agent absorbs its own LLM failure | One rate-limited call should not surface as a 500 to a user who asked a reasonable question | An outage looks like a degraded answer rather than an error page |
| `NOT_FOUND_IN_CONTEXT` sentinel detected and stripped in `finalise` | Leaking the sentinel turns an honest refusal into an unreadable protocol error | A magic string that both prompt and code must agree on |
| Answer buffered, then replayed in ~6-word frames | The critic must read the whole draft before any of it streams | Several seconds of first-token latency, mitigated by `status` frames |
| Per-node `status` frames | Verification means seconds of work before the first token; an unlabelled wait reads as a hang | Two more event types in the wire contract |
| `agent_trace` persisted with the message | "The critic rejected the draft twice" is the information you need when an answer looks evasive — and it is the difference between debugging and guessing | Storage, and a UI disclosure to build |

## Hardening

| Decision | Why | What it cost |
|---|---|---|
| Hand-rolled sliding-window limiter instead of `slowapi` | The rule is three lines and a deque; a dependency would also have had to learn that chat is per-owner and login is per-address | Per-process state: a second worker doubles the allowance |
| JWT (`PyJWT`, HS256) with `sub = owner_id` | The owner id must not be client-forgeable, and a signed token with `exp` is the smallest thing that guarantees it | A secret to manage, and a login round trip |
| `JWT_SECRET` refused at boot under 32 chars | RFC 7518 minimum for HS256; PyJWT warns on every call otherwise | A confusing first boot if you paste a short secret |
| `X-Demo-Key` accepted only outside production | Keeps local work frictionless without shipping an unauthenticated identity path to the deployed demo | Two code paths in one dependency |
| Access log is **pure ASGI**, not `BaseHTTPMiddleware` | `BaseHTTPMiddleware` wraps the response body in its own stream — exactly wrong between a chat endpoint and an SSE stream that must flush frame by frame | Hand-written scope/receive/send plumbing |
| `request_id` in a `ContextVar`, not a parameter | The call sites that want it are twenty frames below the middleware; none should take a logging parameter | ContextVars are copied into Starlette's threadpool — verified, not assumed |
| Client-supplied `X-Request-ID` bounded to 64 chars | Not a secret, but a caller could otherwise stuff a kilobyte into every log line and back out of the response | Long trace ids get truncated |
| `/api/health` never touches a dependency; `/api/health/deep` does | Render restarts a container that fails its health check, so an Atlas blip must not become a restart loop | Two endpoints, and one is unauthenticated (up/down only, no versions or names) |
| Deep health reports the exception **class**, never its message | pymongo and Pinecone both put the connection string — with the password — into their exception text | Slightly less detail when debugging |
| CORS allowlist from config, never `*` | A wildcard lets any website in the world spend your Groq and Pinecone quota on a stranger's behalf | One more env var to set correctly at deploy |
| Extension + size validation before parsing | A hostile PDF should cost nothing but the request | Two rejections to explain in the UI |
| Rate limit enforced before reading upload bytes | Otherwise the limit only bounds the damage after the damage | — |
| Argon2id at `m=19456,t=2,p=1` for passwords | Memory-hard, so a leaked hash table cannot be attacked with a GPU the way bcrypt can; these are OWASP's floor for a constrained server, and Render's free 512 MB with one shared CPU is what caps it above that floor | ~20 MiB and tens of ms per login, so the suite hashes for real and is slow |
| The password policy lives in `create_hash`, not only in the request model | Hashing is one module's job, so a future caller that forgets to validate still cannot store a weak hash | A second place a 422 can originate from |
| `blind_verify()` on the no-such-account login path | "Unknown email" answering in 1 ms against "wrong password" in 60 ms is a free oracle for enumerating who has an account | Every failed login costs a hash, including the ones that found nothing |
| A random hex `user_id`, not an ObjectId | The account id ends up inside a verification link; a sequential one makes "this address registered, and so is the next" guessable | A 32-char key where 24 would have done |
| `email` normalised to lowercase by one shared function, then enforced by a unique index | Two spellings of one mailbox would otherwise become two accounts with two hashes, and the index is the only place a concurrent duplicate can be seen | Case-insensitive login, and a `ValueError` for an address too long to receive mail |
| A verification token and a session token share one signing key and are told apart by the `purpose` claim | One key and one mint helper is less to get wrong than two secrets, but a link that sits in an inbox must not also be a credential — so `owner_from_authorization` refuses any token that carries a purpose | `sub` means "owner id" in one token and "user id" in the other, so each decoder has to know which it is reading |
| Register and resend answer an identical 202 whether or not the address is an account | Those two endpoints otherwise hand back a free oracle for "is this mailbox registered here", which is the same enumeration the login path spends an Argon2 hash to avoid | A visitor who mistyped their own address is told the link is on its way and never gets one |
| Login's 403 "confirm your email first" is the one place the API admits an account exists | Someone whose only mistake was not clicking a link deserves a different sentence than someone with the wrong password, and the leak is narrow: it reveals an account that cannot do anything yet | An attacker can list registered-but-unverified addresses; documented as a deliberate trade |
| Account endpoints are sync `def`, not `async def` | Each performs a blocking Mongo write and, for register and resend, a mail send with a bounded 10 s timeout — on the event loop that would freeze every chat stream in flight for the duration | The threadpool is bounded, so a mail provider that hangs ties up worker threads instead |
| The verification link is built from `FRONTEND_BASE_URL`, never from the request's `Host` | Behind Render the host header is the API's own domain, so deriving it would send every visitor to `onrender.com/verify`, and the header is client-controlled anyway | Renaming the frontend domain is a commit and a restart, not a click |
| Every live mail transport is refused at boot without its credentials | The alternative is a service that reports healthy, returns 202, and never delivers anything — the worst failure shape a mail system can have | A confusing first boot if you flip the transport before pasting the secret |
| Deployed mail goes out over **HTTPS**, not SMTP | Render's free instances block outbound traffic to ports 25, 465 and 587, so Gmail's relay is unreachable from this host no matter what the credentials say; the failure is a silent dropped SYN that surfaces as a 10 s timeout and an `OSError` | One more transport, one more provider, and a sender address that has to be verified there before it can be used |
| stdlib `smtplib.SMTP_SSL` to port 465 instead of a mail SDK | Implicit TLS is what Gmail offers there, the whole send is six lines, and `requirements.txt` is the file that decides whether the image still fits in 512 MB | No queue, no retries, no delivery receipts — a failed send is the visitor's problem, and resend is the retry |
| stdlib `urllib.request` for the API transport too, rather than the `httpx` already in the image | One POST with a fixed body does not justify a declared dependency, and the reasoning that chose `smtplib` over a mail SDK should not change because the port did | No connection pooling, and a response read that has to be done by hand |
| A refused send logs the provider's **status code**, not just the exception class | `error=HTTPError` is three unrelated faults wearing one name — wrong key, sender Brevo will not mail from, account not cleared to send — and the integer status is the only field that separates them without being a credential | The response body on `exc.fp` stays unread, so the provider's own explanation of the failure never reaches the log stream |
| The verification mail is text-only, with no HTML part | The message contains one link and one sentence of consequence; an HTML template is a second artefact to maintain and a spam-score to tune | Looks plain in a busy inbox |
| A password that verifies is rehashed when the stored cost parameters are older | Sign-in is the only moment the plaintext exists, so it is the only moment the parameters can be raised without asking everyone to choose a new password | One extra hash on the first login after a parameter change |
| Accounts shipped as three PRs — endpoints, then UI, then deletion of the code | Render and Vercel both auto-deploy from `main`, so an endpoint and the screen that calls it cannot land in one commit without one of them being broken mid-flight. The coexistence window was a release, not a state | Two identity paths for a few days, and a dashboard env var that had to be deleted before the last merge could deploy |
| The access-code gate is deleted rather than left as a fallback | Two ways in means a visitor can reach a namespace no account owns, and the seeded demo account plus `/auth/login` cover every case the code served. Half a migration is the part a reviewer judges | Anyone with a tab open from before the deploy gets a 404 and signs in again |
| One shared, pre-confirmed demo account, its password published in the README | A reviewer with no second inbox has to get in, and a demo whose first step depends on a stranger's spam filter is not a demo. `scripts/seed_demo_user.py` makes it one command rather than a hand-edited row | Everyone who uses it shares one namespace and one rate-limit bucket, and the next visitor can read the documents the previous one uploaded |
| `Settings` refuses to boot on an unrecognised env key (pydantic-settings' `extra=forbid`) | A typo'd variable name is otherwise a silent misconfiguration, and the mail transport in particular has a fallback that would hide it | Retiring a setting is a two-step deploy: delete the dashboard key, then the field — in that order |
| The signup bucket is per address over an **hour** (`window_seconds=3600`), where every other limit is a minute | The budgets that accumulate are rows in a 512 MB Atlas cluster and mails sent through one Gmail account, which punishes a script that hits its quota by the minute; a minute-long window still permits hundreds of accounts per hour | Someone who mistypes their address and immediately wants the link again spends a second slot of a scarce bucket |

## Frontend

| Decision | Why | What it cost |
|---|---|---|
| One `lib/api.ts` owns every fetch | Auth headers, error unwrapping, and SSE decoding live in one reviewable file instead of per component | A slightly fat module |
| Manual SSE body reader, not `EventSource` | `EventSource` only does GET and the question must travel in a body | Buffering, frame-splitting, and a trailing-frame check |
| Session in a `useSyncExternalStore` over `localStorage` | Avoids `setState` in an effect and the hydration flash a naive version produces | A store module and a `SESSION_PENDING` server snapshot |
| `Workspace` keyed on `ownerId` | Switching owners must not leave the previous corpus on screen | A remount on sign-in (which is the point) |
| 401 anywhere clears the session and shows the sign-in panel | A wall of failing requests is worse than one honest "sign in again" | A global side effect in the error path |
| Inline `process.env.NEXT_PUBLIC_*`, never destructured | Next only inlines literal member expressions into the client bundle | Repeated spelling of the same variable |
| Password held only in component state; the email is stored | A token outlives the tab and a password must not, but prefilling the address is what makes "sign in again tomorrow" one keystroke — it is not a credential and the browser already knows it | A shared laptop shows the previous visitor's address in the box (not their session) |
| One panel, two modes, for sign-in and sign-up | Both ask for the same two fields, so they share the inputs, the error slot, the busy flag and the 403 branch; only the endpoint and the closing sentence differ | A mode toggle to keep honest, and a `minLength` that only applies to one of them |
| The 403 is the only refusal the panel acts on | "Confirm your email first" has a next step the app can take — send the link again — so it renders a button instead of a sentence. A 401 renders the server's words and no theory, because the backend deliberately cannot tell a wrong password from an unknown address | Two failure shapes to style, and a UI that is chatty about one and mute about the other |
| `useSession` stopped exposing `submit` | The panel needs the field state, the busy flag and the 403 branch next to the submit call; threading all three through a hook two other panels use widened it for nobody | The panel imports the store directly, so it has two sources of truth for auth — the store, not the hook |
| `/verify` reads its token inside a `<Suspense>` boundary, with the card as the fallback | Under Cache Components a route that reads the query string with no fallback cannot prerender at all — `next build` fails rather than serving the page. The fallback is the same card the client replaces, so nobody sees a blank screen between the inbox and the answer | Three files for a page that is one POST and one sentence |
| The token is stripped from the URL once spent | The link works once and lasts a day, so a reload, a history revisit, or a screenshot into a chat would otherwise carry a live credential for someone else's address | The address bar briefly shows `/verify` with no explanation of what just happened |
| `/verify` has a layout that only exports a title | Metadata must live in a Server Component and the page is a client component; "Confirm your email" in the tab is also the cheapest proof the link went where it said | One more file, and a `LayoutProps<"/verify">` that breaks if the route moves |
| A marker is recognised only in its complete `[n]` form, so the split captures the closing `]` | `String.split` hands back exactly what a capture group matched. Capturing `[\d+` without the bracket made every piece unrecognisable to the full-marker test, so citations rendered as `[1` in the prose and the `]` was consumed by the split — readable text, so no build, lint, or click-through flagged it | Two regexes that have to agree, and one test per shape: single, chained `[1][3]`, two-digit, and brackets that are not markers |
| A `components/ui/` layer of five primitives, and panels that stop carrying class strings for anything shared | Twenty buttons and six banners were typed by hand per panel and had already drifted — one disabled button kept its brand colour while another greyed out, the same "Sign out" action existed in two visual weights, and the spinner was three copies of two designs. Each copy was defensible on its own; nobody could say which one was the design | Five more files, and controls that are genuinely one-off (the citation chips, the Dismiss button) deliberately left raw so the primitive does not become a straitjacket |
| A variant owns its hover and disabled colours; a caller cannot replace them with `className` | Two `hover:` utilities in one class list sit in the same specificity band, so the winner is decided by the order Tailwind emitted them, not the order they were typed — `outline` plus `hover:text-red-300` loses roughly half the time and always loses silently. Hence `outlineDanger`, and hence the header's `hidden lg:block` living on a wrapper `<div>` rather than on the button it hides | A variant per hover state instead of a tweak at the call site, so a genuinely new colour means editing the primitive |
| `busy` is a separate prop from `disabled`, and it freezes the idle colours | A control mid-request that greys itself reads as "this broke" when the truth is "the server has not answered yet". So the spinner-bearing state keeps the colour it had when it was pressed and only sets `aria-busy` plus `cursor-not-allowed` | Two states to style per variant, and a caller that must pass both — the submit button is `busy` *and* `disabled`, and `busy` wins the colour so the click stays blocked by the browser without the button looking broken |
| Split the answer parser, the trace labels and the byte formatter out of their components into `lib/citations.ts`, `lib/trace.ts`, `lib/format.ts` | Each is logic with edge cases that a DOM renders invisibly — the marker run `[1][3]`, a node name the graph renamed, a file one byte short of a megabyte. Tested as functions, those are seven assertions in 15 ms with no component tree to build; tested through a render, they need a bubble, a citation list and a stubbed `scrollIntoView` each | Three modules whose only caller is one component, so reading the render still means opening two files |
| A document row owns its delete confirmation | With one panel-level `confirming: string \| null`, opening a second row's question closed the first — behaviour nobody chose, only what a single id made easy — and every row re-rendered on any row's click | Two rows can now be mid-confirmation at once, which is what the test asserts and what a reviewer may call a regression |
| Which citation is open stays in `Message`, not in `SourceList` | Two children set it: the `[n]` button inside the answer and the source row below it. The repo rule for that is the parent holds it and passes it down, same as the workspace panels | `SourceList` is not self-contained — it takes `openIndex` and a toggle instead of owning its disclosure |
| The keyboard ring is `tokens.FOCUS`, not a `Button` variant | Only `Button` can be a `Button`: a `<label>` for an upload, an `<input>` for the scope checkbox, and a glyph absolutely positioned inside a field must stay raw — and the raw controls disagreed with each other about what focus looks like. `FIELD` and the password eye button both carried `focus:outline-none`, so keyboard focus there was invisible; the rest fell back to the browser's own light ring, a second focus language one tab stop away from the first. Now both kinds of control read one string | Nine raw controls interpolate `${FOCUS}` — the citation chip, the source and history rows, the scope checkbox, select-all, the trace disclosure, the Dismiss link, the mode switch and the password eye — and `tokens.FIELD` carries it for every text input. The hidden `<input type="file">` is exempt on purpose: a keyboard user reaches it through the Upload button, which has the ring, and the checkbox's ring is the one assertion in `document-row.test.tsx` that a reviewer can least re-check by eye |
| Icons are inline SVG with `aria-hidden`, not characters | The row's cross was the only icon typed as a glyph, so its size and baseline followed the button's font rather than its `size` prop, and it was announced as text where the button already had an `aria-label` naming the file. `icons.tsx` keeps the paths, the `h-4 w-4`/`h-3.5 w-3.5` defaults, and the `aria-hidden` in one place | Two more components to import, and a `fill="none" stroke="currentColor"` contract that each new glyph has to honour |
| Chunk and page counts agree with their numbers | The deployed demo corpus is one file of one chunk and one page, so the first sentence a reviewer reads about their own upload was "1 chunks · 1 pages" | Two ternaries in the row, and a test per singular form |
| `ui/EmptyNote` is the box every empty list uses | Three sentences did that job — "Loading your documents…", "Nothing uploaded yet.", "No conversations yet." — in two greys and two line heights, and each was a plain line of small grey text in a sidebar that is already a column of small grey text, so an empty state read as furniture rather than as an answer. The dashed box says *nothing here yet* at a glance and the words say which kind of nothing | A primitive with one job and three call sites; the box costs the sidebar four more lines of height than the sentence did, and it has to render an `<li>` — a list that returns a `div` between its items is markup a validator complains about while every browser renders it anyway |

## Deployment and dependencies

| Decision | Why | What it cost |
|---|---|---|
| Monorepo, one repo for both apps | Simplest to manage solo; `render.yaml` and Vercel's root-directory setting both handle it | Two toolchains in one `git status` |
| Multi-stage Docker, `python:3.11-slim` | The builder layer keeps pip's cache and build tools out of the runtime image | Two stages to reason about |
| Pin `torch==2.15.0+cpu` from PyTorch's CPU index | The default wheel drags ~2 GB of CUDA runtime into a container that will never see a GPU; 512 MB RAM is the binding constraint | A pin that must be re-checked when sentence-transformers is upgraded |
| Bake the embedding model into the image | Otherwise the first question after every cold start spends seconds and ~100 MB of egress downloading MiniLM — and a "no network to HF" failure becomes a failed build instead of a container that never answers | A larger image (~100 MB) and a slower build |
| Non-root container user, `PYTHONUNBUFFERED=1` | The container should not be able to write its own layers; and block-buffered stdout makes Render's JSON log stream lag | Two extra Dockerfile lines |
| `.dockerignore` with context = `backend/` | Docker tars the whole context before the first RUN; a root-wide context would upload `frontend/node_modules` on every build | One more file to keep honest |
| `render.yaml` with every secret `sync: false` | The deployment shape becomes reviewable source; a Blueprint with a literal key in it is the same mistake as committing `.env`, applied automatically to every copy | Values still set by hand, once |
| `CORS_ORIGINS` is the one exception: a literal in `render.yaml` | It is not a secret — the server echoes the origin in every preflight response — but it is load-bearing, and a value that lives only in a dashboard can be dropped by a sync with no diff to review | The Vercel domain is hard-coded, so renaming it is a commit, not a click |
| Accept Render cold starts; do not cron-ping | Being explicit about a real constraint beats hiding it, and a keep-alive cron burns the 750 free instance-hours | A measured 81 s first request after idle, with UI copy that says so |
| Pins copied from the working venv, not guessed | "Works locally, dead on Render" is usually a drifted transitive dependency | Manual re-pinning on upgrades |
| Model name in `GROQ_MODEL`, default `qwen/qwen3.8-27b` | Groq retired the `llama-3.1-8b-instant` this was built against, so a hard-coded pin became a provider error on every call; and reasoning models (`openai/gpt-oss-*`) are not substitutes — they bill hidden thinking tokens against `max_tokens`, and the router asks for 48, so it answers `''` and loses document scoping | A default that will itself age out, and a test to keep the pin in config |
| `PyJWT` listed explicitly | A direct import that arrives only as somebody else's transitive dependency is how a deploy one day cannot find `jwt` | One more pin |
| pytest and ruff in `requirements-dev.txt` only | Test tooling must not ride into an image with a 512 MB RAM budget | Two requirement files |
| `MAIL_TRANSPORT` declared `sync: false` in `render.yaml`, not as a literal | A Blueprint sync rewrites dashboard values from the file, and the failure it produces is invisible: every visitor keeps getting a 202 while the link only reaches the application log. The transport is the one setting that legitimately differs between a clone and a deployment, so the dashboard owns it | Enabling real mail is a dashboard edit and a restart, which is one review step weaker than a commit |

## Testing

| Decision | Why | What it cost |
|---|---|---|
| Mock the LLM, never the pipeline | LLM output is non-deterministic and costs quota; everything else is deterministic and free to test | A fake model to maintain |
| A separate `test_llm_retry.py` with a model that *fails* | The agent tests need a model that answers; the interesting rules are in the failure paths — which statuses retry, how long the user waits, and never restarting a stream that already showed words | A scripted stub per failure shape |
| Assert the **query shape** against fakes that record calls (`test_vector_store`, `test_metadata_store`) | An in-memory fake store never notices a missing `owner_id` filter — which is the one bug class that leaks another user's documents | Tests that break when a filter is legitimately restructured |
| Fake method signatures spelled out, never `**kwargs`, plus one test that reads the installed SDK's signature | The first version of this fake took `**kwargs` — exactly like the real client — so it recorded `filters=` happily while production dropped it. 202 tests were green through a live cross-owner leak | A fake that must change when the client's signature changes, which is the moment worth being told |
| The fake `users` collection refuses a write that breaks a unique index | A fake that accepts every insert would let two accounts for one address through and the signup endpoint would still look correct — the same permissiveness that hid the `filters=` leak | The fake has to know which indexes the real collection declares |
| One test asserts `InvalidHashError` is *not* under `Argon2Error` | argon2-cffi raises a `ValueError` for a hash it cannot parse and an `Argon2Error` for a wrong password, so a single-tree `except` turns a malformed row into a 500 on the login path. Mocking the hasher could never reveal this | A test that reads a dependency's exception tree, which is a thing to update on upgrade |
| Tests run in `development` mode by default; `production_mode` (in `conftest.py`) flips it per test | Keeps the older tests on the `X-Demo-Key` path while production-mode rules get real coverage; the fixture moved out of `test_auth.py` the moment the account tests needed the same flip | Two mode conventions in one suite, and one more shared fixture to read |
| The mail transport is faked by capturing the link, and the test then decodes it | What matters about a verification link is where it points and what claims it carries — and CI owns no mailbox.
